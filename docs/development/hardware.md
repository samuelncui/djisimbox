# 硬件验证与兼容范围

本文保留现有部署记录中可公开复用的结果与限制。验证针对一组设备和 SIM 条件，不能替代其他模块、固件或运营商组合的验收；本次发布整理未连接硬件或重复实验。

## 被测组合

| 项目 | 已记录条件 |
| --- | --- |
| 主板 | Orange Pi Zero 2W，Armbian / Debian 13，Wi-Fi 管理与 Internet。 |
| 模块 | DJI 第一代蜂窝模块，USB `2c7c:0125`，报告为 BAIWANG EG25G-QDC507。 |
| 固件 | `QDC507GLEFM21_01.001.01.005`，定制固件；通用 USB 名称不足以辨认兼容性。 |
| 主机接口 | ECM `cdc_ether` 网口和 USB 串口；短信与被动来电由 ModemManager 接入。 |
| ModemManager | 1.24.0，Quectel 插件可读取 SIM、Messaging 与 Voice 属性。 |
| 短信存储 | `ME`，报告 255 个槽位；这不是长时间断网的容量保证。 |

## 已确认结果

- USB 身份匹配的 networkd 规则在网口改名、模块重启重新枚举和已观察的主板启动后保持生效：蜂窝网口关闭、无地址，默认路由走 Wi-Fi。
- 主机网口受保护时，真实入站 UCS2 中文短信可被接收并投递到 Telegram。
- 在最终 RAM 服务中，新的短信经历入队、Telegram 成功、原件删除与队列释放；服务可由专用账户独立运行，未使用 NAS 或网络存储。
- 原 CU 配置下的来电测试未到达应用。切换模块自带的 `ROW_Generic_3GPP` 后，IMS 查询变为 `1,1`，可见 PDP 配置出现 `ims` APN；随后真实呼入与短信均完成 Telegram 投递，操作方确认来电和通知可达。
- 来电确认只释放本地通知状态，不调用呼叫控制。短信原件在 Telegram 成功后释放；当时主机蜂窝接口仍关闭且计数无新增流量。
- 运行目录与专用 journal 使用 tmpfs，状态报告 `storage: memory`；空闲样本未见应用存储写入。该样本不构成长期运行、负载或整个操作系统的零写入保证。

通知标题和元数据格式在真实收件验证之后统一为当前布局，该格式有自动化覆盖。现有记录没有该格式更新后的新一轮真实收件验收。

## IMS 与主机流量的边界

被测 ROW 配置的 `AutoSel=0`、IMS override 为 `1`，主机侧自动连接设置读回 `0`。这些是特定实验结果，不作为安装脚本的默认修改。详细原因与公开依据见[VoLTE 研究](volte-research.md)。

主机网口的地址、路由和字节计数只覆盖主机数据路径；它们无法证明模块内部没有 IMS 注册、信令或数据流量。LTE 已注册、`EmergencyOnly=false`、Voice 接口存在、IMS `1,1` 或出现 `ims` APN，各自都不能单独证明真实来电可达。

[ModemManager 的 LTE bearer 说明](https://modemmanager.org/docs/modemmanager/ip-connectivity-setup-in-lte-modems/)解释了初始 bearer 与主机配置的区别。计费取决于 SIM 套餐、归属/漫游网络与运营商，项目不能承诺无漫游费用。

## 仍需硬件验证

- 完整断电后，模块是否保留未删除短信，以及重新启动后的重复投递边界。
- 受控物理拔插，包括供电稳定性、网口保护与 ModemManager 重建。
- 多 modem 同时工作时的供电、USB 容量、身份隔离及投递。
- 多段长短信、网络长时间中断和存储满时的实际表现。
- 其他 SIM、运营商、漫游组合、模块及固件的短信与来电验收。

一般验收步骤见[用户运维说明](../user/operations.md)。更换硬件时先确认主机保护规则匹配实际 USB 身份，再分别完成真实短信和来电的 Telegram 闭环；不要只据 AT 状态或模块型号判断成功。
